## [Unreleased]

### Added
- **The diagram editor (RF-31) gets its own entry in the Tools menu (RF-45).** It used to be reachable only as one icon among roughly twenty in the editor's insertion toolbar — "very hidden away", in the user's words. The toolbar icon is kept as an extra shortcut; both routes open the same editor.
- **New "Flow with decision" seed template in the diagram editor (RF-47).** The editor already supported a diamond-shaped node and text on an arrow since v0.6.0 — exactly what a decision diamond with "Yes"/"No" branches needs — but no template showed it off, so the capability went unnoticed. No new Typst Universe package was added: an example was all that was missing (see `ADR-DECISION-001` in `memory.md`).

### Changed
- **Decorative illustration in the launcher's top-right corner**, based on an image the user provided: fully transparent around the blue linework, so it reads well on all three themes without a per-theme variant. It's removed on narrow windows (<900px) so it doesn't compete with the headline or the cards.
- **Save, Save As, Export PDF and Export PNG move from the document bar to the File menu (RF-43).** They used to live as loose icon buttons, duplicating what that menu already does. Same full labels and shortcuts as before; they're disabled (not hidden) without an open project.
- **Second redesign of the home screen, based on a visual reference the user liked better than the first RF-44 pass.** The "New document" button now spans the full width on its own (it used to share a row with the secondary actions) and gets decorative corner marks. The four secondary actions (Open folder/Open .typ/Import .dbvt/Clone repository) move from a row of buttons to a 2x2 grid of cards with an icon, a short title and a one-line hint. "Recent projects" is rewritten as a compact divider list (icon, name, trimmed path and **relative time** — "today"/"yesterday"/"3d"/"1w"/"2mo" — instead of self-bordered cards), and gains a "View all" link that expands the list up to the 10 entries the backend already stored (only shown when there are more than 5). The "What do you want to write today?" headline moves to a serif typeface, an editorial nod that doesn't touch the sans-serif type used everywhere else in the app.
- **Redesigned "Recent projects" cards (RF-44), first pass.** Each entry showed an icon for whether it was a project folder or a loose `.typ` file, and the containing folder's path trimmed to its last two segments (with the full path available on hover) instead of the untrimmed full Windows path, with the visible list capped at the 5 most recent entries. Superseded by the redesign above in the same session — the on-disk history (up to 10 entries) never changed, only how it's presented.

### Added
- **DOT/Graphviz assistant (RF-51).** New, in the Tools menu: a text field where you write or paste a graph in DOT syntax, with its REAL preview right below — compiled by Typst on every pause (~105ms average measured), just like the equation editor. No catalog of pieces at all: anyone using this already knows or already has the DOT written. Generates the graph with the `diagraph` package (MIT license, renders via a Wasm plugin with no installed Graphviz required), adding its import only when needed.
- **Kanban board assistant (RF-50).** New, in the Tools menu (▥): add columns and, inside each one, its cards (name, optional assignee, hardness and priority). Generates the board with the `kantan` package (AGPL-3.0-only license, documented as-is in the Universe Browser — it doesn't affect the generated document or the app, which never vendors the package), adding its import only when needed. Fixed color palette per column, no picker — same "four data points" criterion that already favored Gantty over Timeliney.
- **Gantt chart assistant (RF-49).** New, in the Tools menu (▤): add tasks with their name and their real start and end dates (native date picker). Generates the diagram with the `gantty` package, adding its import only when needed.
- **Sequence diagram assistant (RF-48).** New, in the Tools menu (⇄): add participants and the messages between them in the order they happen, with optional text and a dashed stroke for replies. Generates the diagram with the `chronos` package, adding its import only when needed.
- **Visual, interactive equation editor (RF-46).** New, in the Tools menu (∑): a text field with the formula's Typst code and, right below, its REAL preview — compiled by the actual Typst compiler on every pause (~80ms average measured before committing to this approach), not approximated by a third-party math-rendering library. 27 one-click pieces (fraction, exponent, subscript, square and nth root, summation, integral, product, limit, 2×2 matrix, Greek symbols, relations and delimiters), plus "Paste LaTeX" for anyone who already has a formula written in that syntax (converted with the MiTeX package). The formula is not added to the document until you press "Insert"; a syntax error mid-edit keeps the last preview that did compile instead of leaving the preview blank.
- **Contextual zoom with keyboard and wheel (RF-42).** Ctrl++/Ctrl+-/Ctrl+0 and Ctrl + mouse wheel adjust the editor's font size when the cursor is inside it, or the preview's zoom when the mouse is over it — intercepting the webview's native zoom, which used to catch them at the system level without the app ever knowing. With neither in focus, nothing happens (it never falls back to native zoom). The editor's font size is remembered across sessions.

### Fixed
- **The benign `ResizeObserver` notice no longer shows up as an application error (RF-40).** Dragging the splitter between the editor and the preview used to trigger Chromium's "ResizeObserver loop completed with undelivered notifications" message, which the global error handler displayed in the red banner as if it were a real failure. It's now filtered by Chromium's own stable substring; any other real error still shows up unchanged.
- **The preview splitter no longer gets "stuck" when the window is maximized (RF-41).** Reported and confirmed live by the user. Cause: `max: 1200` was a fixed pixel cap unrelated to the actual window width — on a wide maximized monitor, 1200px stops feeling like "all the available space" and dragging cuts off abruptly with plenty of unused room to the right of the editor. It now scales with the real window width, with no absolute ceiling.
- **The launcher's secondary actions row (Open folder/Open document/Import/Clone) carries less visual weight.** They still read as "a row of buttons" next to the primary button even though they were already structurally subordinate (RF-44): they now carry no border or background at rest, only on hover or focus.

## [0.6.0] - 2026-09-13

### Added
- **"Packages" and "Search" are now real tabs in the Typst Universe panel, and that same search is reused in "Create document from template" (RF-34.6, RF-34.7).** Two requests from the user in the same conversation after trying the previous fix. (1) The curated list and the full catalog stop sharing the same stacked screen — "confuses a lot", in the user's words — and become two independent tabs, same pattern as the sidebar's Files/Outline tabs: each grid gets the whole panel to itself. (2) The search engine was extracted into `universe/universeSearch.js` so it can be mounted in the Template Gallery too, in a "Search" tab that replaces the old "Address" one — there it searches templates ONLY (`filterEntries`), since that screen creates projects, it doesn't import packages. Picking a result doesn't download anything on its own: it just fills in the address below, exactly as if typed by hand, leaving "Download and preview" as the only thing that touches the network (RF-26.6 untouched).
- **The full Typst Universe catalog search (RF-34) now tells a package apart from a template.** `index.json` mixes the two in the same list — nearly half of the ~4,700 entries are templates — and a template entry (e.g. `campanile`, a UC Berkeley thesis template) was inserted as `#import` into the open document, which isn't how a template gets used: a template is CREATED, not imported. Every entry now carries `isTemplate` (derived from whether it has the real index's `template` key, verified against a full download), the card says so ("📄 Template — creates a new project"), and clicking "Use" on one closes the search and opens the Gallery on the "Address" tab with the identifier already filled in, ready for "Download and preview" — without touching the open document or downloading anything on its own (RF-26.6 still holds).
- **An inserted image now arrives with its `<fig:...>` label, ready to reference.** It previously had to be typed by hand before the figure could be cited with `@fig:...`. The label is derived from the file name (`images/diagrama-1.png` → `<fig:diagrama-1>`), stripping accents and any character Typst doesn't allow in a label. It also checks the label isn't already in the document, numbering it if so: **a repeated label is a compile error in Typst**, so inserting the same image twice would have broken the whole document. Applies to all three entry points: drag, paste and the toolbar's "Fig" button.
- **Paste an image from the clipboard (RF-39).** Snipping a region of the screen and pasting it into the document did nothing — and it wasn't a bug, it was an absence: the app had no `paste` handling at all. The image is now saved into the active project's `images/` folder and the figure inserted with its relative path, never embedded as a `data:` URL. If the editor doesn't have focus the image is still copied and the path reported, the same rule RF-18 settled for drag and drop. Pasting text keeps working exactly as before: the paste is only intercepted when the clipboard carries an image file and no plain text, because copying text from a web page sometimes drags a decorative image along with it. `image/bmp` is rejected — Windows puts it on the clipboard often — because Typst can't embed it and it would leave a file that breaks compilation, and pasting the same snip twice reuses the file already saved.
- **Documented the Typst Universe rich hover (RF-34.5).** The tooltip that appears when hovering `@preview/name:version` in the editor, with a direct link to `typst.app/universe`, has existed since v0.5.0 but was never written down as a requirement in `SPECIFICATIONS.md` — a finding from the manual pass, no code change.
- **New .typ file from the project tree.** "+" button next to the Files panel filter: creates a file at the active project's root and opens it. Closes a real gap surfaced while testing RF-33 in the real window — cloning an empty GitHub repository left an open project with no way to create the first file, because the template wizards always create a new folder, never add to one already open.

- **Diagram editor arrows get direction, stroke and text (RF-31).** Requested by the user after comparing with the [hilbert-editor](https://github.com/aburousan/hilbert-editor) canvas. Clicking a connection opens its property row: arrowhead at the end, at the start, at both ends or none; solid or dashed stroke; and a text drawn over the arrow — the "yes"/"no" coming out of a decision diamond. **Triangle** and **hexagon** join the palette too (six shapes now, enough to draw a complete flowchart without leaving the canvas), and the **figure caption and its label** are editable, so the diagram can be cross-referenced with `@fig:...` from the text instead of being stuck as "Diagrama" forever. Verified by compiling: an arrow's label is placed with a **percentage** (`("n1", 50%, "n2")`), not the number `0.5`, which CeTZ reads as a distance in canvas units and left the text sitting on top of the source box instead of halfway along.
- **The WYSIWYG diagram editor (RF-31) gains shapes, colours, zoom and panning.** Second pass after the user's feedback ("it only lets you add boxes, no colours"), taking **dbv-eer-studio** — the other diagram editor in the family — as the reference: a palette of four shapes inserted with one click (rectangle, rounded rectangle, ellipse and decision diamond), six colours with fill and stroke already paired up, zoom by wheel and buttons (±, fit) and panning by dragging the canvas background. Labels are now **fitted inside the shape** instead of being anchored to its centre: verified against the real compiler, anchoring them by name let long text spill out of the box on both sides. CeTZ has no diamond primitive, so it is generated as a closed four-point polygon.
- **Every floating window can now be closed and moved.** Until now only Terminal, Python, Git, Help, About and Universe had a header with "✕"; the rest (symbols, table, citations, images, bibliography entry, CeTZ assistant, diagram editor, clone repository) could neither be closed with a button nor repositioned. The header is now added in `registerPanel()`, the factory every panel goes through, so a new panel inherits it without anyone having to remember — which is exactly how half of them were left behind. Dropdown menus are deliberately excluded: they close themselves on selection.

### Fixed
- **The Gallery's metadata footer (title, version, files) kept showing a completely different template after downloading and previewing an identifier on the "Address" tab.** The canvas DID correctly show the downloaded layout, but the footer below never refreshed on that path — it stayed with the data of the last template picked on a DIFFERENT tab (e.g. "Academic article" while the canvas showed a freshly downloaded Berkeley thesis template). Extracted `renderMeta()` out of the rest of `renderPreview()` and wired it to typing in the field and to a successful download too, so it never depends on which tab was visited before.
- **In the Typst Universe panel, the full-catalog search field (RF-34) sat wedged right in the middle of the window, with the curated grid above and the results grid below each cropped to a couple of rows.** Both grids shared `flex: 1 1 auto`, so each ALWAYS claimed half the panel's height, whether or not a search was active — the curated grid could never show more than a couple of rows, and neither could an active search's results. The curated grid now takes only what it needs (with its own scroll if needed), and the results grid is the only one that claims the leftover space.
- **Render→editor sync (RF-16) could jump to the NEXT chapter on a double-click anywhere in the current chapter.** Found with a real thesis project, in two rounds on the same symptom. (1) Many thesis templates force a new page per chapter with `show heading.where(level: 1): it => { pagebreak(weak: true); .. }`. The sync anchor was seeded as a sibling BEFORE the heading, so it was laid out (position and all) BEFORE that page break fired — it stayed anchored to the LAST page of the PREVIOUS chapter. Fixed by seeding a heading's anchor AFTER it instead of before, so it inherits the new page. (2) The same symptom resurfaced one chapter in: every chapter in the template opens with a comment header and an `#import` before the title, and those two lines — which produce not a single pixel — were still anchored BEFORE themselves, inheriting the SAME ghost position the heading had before it was fixed. A double-click on the equation block at the end of "2.2 Métricas" (tall enough to reach that position) jumped to the next chapter. A comment or an `#import` no longer get an anchor at all — there's no click they could ever correspond to. Verified against the real thesis that reported it, with the actual production code: all 19 PDF pages come out byte-for-byte identical to the original in both rounds.
- **Found along the way, a related bug in the same real project: a sync `#metadata` leaked as literal text inside a fenced code block (` ```python `).** The nesting tracker that decides "this is top-level markup" didn't recognise backtick fences (only `{`, `[`, `(`), so a code line inside a listing was mistaken for markup and got a visible anchor in the compiled PDF — and pushed the rest of the document one whole page over. The same thesis, with its Python/R/C++/SQL/Bash "code snippets" appendix, surfaced it.
- **Arrowheads were invisible on the diagram editor canvas, even though they showed up in the compiled PDF.** Real cause: the canvas drew every arrow **centre to centre** between nodes, and since nodes paint on top of arrows, the arrowhead ended up hidden **underneath the target node's box**. The PDF was fine because CeTZ clips the line to the named shape's border by itself — which is exactly why only the preview was wrong. The canvas now clips the same way: each end is computed against the real silhouette (rectangle, ellipse, diamond, triangle or hexagon), so the preview shows what will be compiled. A second problem with the same symptom but a different cause was fixed along the way: an SVG `<marker>` doesn't inherit its line's colour and painted black by default, invisible on the dark theme's canvas; with `context-stroke` it takes its own line's stroke, and a selected arrow turns accent-coloured without needing a second marker.
- **The WYSIWYG diagram editor (RF-31) did not let nodes be moved or dragged.** `render()` rebuilt the entire SVG inside the `pointerdown`/`pointermove` handlers themselves, destroying the element that had just captured the pointer the instant it started moving — dragging broke on the very first pixel. Full rebuilds (only on add/remove/connect) are now separated from in-place updates (moving a node and its connected arrows no longer rebuilds anything). Verified with `diagramEditor.test.js`, which simulates the real pointer-event sequence against the DOM. Also: two starter templates ("Flowchart"/"Block diagram", same content as the CeTZ assistant) so the canvas doesn't start completely empty, and a plain click now focuses the node's text for direct editing.
- **The CeTZ diagram assistant (RF-23) and the new visual editor (RF-31) inserted code that didn't compile.** Real cause, found by compiling against the vendored `typst` binary, not by reading code: `@preview/cetz:0.3.1` is incompatible with Typst 0.15.1 — the assistant's own "Blocks" example panics with `Failed to resolve coordinate: (0, 0)`. Bumped to `@preview/cetz:0.5.2` in both places. The "Plot" type needed a second import too: since cetz 0.4 the plotting module lives in a sibling package, `@preview/cetz-plot:0.1.4` — `cetzAction()` now injects both imports without duplicating either.
- **A real merge conflict left raw `<<<<<<<`/`=======`/`>>>>>>>` markers inside the document, with no place in the UI to resolve it.** `git status --porcelain=v2` reports conflicted files on a `u ` line that the parser didn't recognize at all — the file vanished entirely from the popover's list, neither modified nor untracked. It's now detected, listed with its own badge and a **"Resolve"** button, and opens a modal to choose, block by block, "Mine" or "Theirs" — anyone who prefers to merge by hand can still close the modal and edit the file directly. It doesn't reuse the existing diff viewer (RF-19.3): that one reconciles the editor with disk after an external change; this one resolves conflict markers Git already left inside a file.
- **The Git popover (RF-19) could not be dragged or closed.** Found while testing the clone flow in the real window: unlike Terminal/Python, it had no close button and no draggable header. Both added, same pattern as the other floating panels.
- **A `pull` blocked by uncommitted local changes showed Git's raw error** ("Your local changes... would be overwritten by merge") instead of an actionable explanation. That specific case is now detected and tells the user to commit first — the commit box is in the same popover. (Not a real merge conflict, which is what the existing RF-19.3 diff viewer covers; this is Git refusing to even start the pull.)
- **The `jogs` assistant example (RF-38) was a trivial sum** (`1 + 1`). Replaced with a real recursive JavaScript function, verified twice against the real `typst` binary before locking it into the code.

**Findings from the v0.6.0 `/code-simplify` review** (8 agents across three passes — Bugs, Security, Compliance — over the full `v0.5.0..HEAD` diff, 59 files):

- **The Git indicator could show "Clean" with an unresolved merge conflict.** The summary only added up modified and untracked files; if the only pending change was a conflict (`conflictedFiles`), the count came out zero and "Clean" was shown — even though the list below correctly showed the badge and the "Resolve" button. A conflict now takes priority and is counted on its own ("N conflicted").
- **Resolving a merge conflict (RF-19.4) left the file flagged "conflicted" until the next commit.** It wrote the fixed content to disk, but `git status` keeps reading the conflict from the INDEX, not the working tree, until something runs `git add`. New `git_add` command (`git add -- <path>`), invoked right after the resolution is applied, so the popover reflects the real state without waiting for a commit.
- **A compile's 45s timeout (RF-38) could kill the NEXT compilation's process instead of its own.** A low-probability but real race: if a hung generation ran out of its margin right as a later one had already started and replaced the "process in flight" slot, the first `cancel_running()` (which never checked whose process it was) killed the healthy new child instead. New `cancel_if_current(generation)`, which only acts if the registered process is still its own.
- **Render→editor sync (RF-16) could leave a heading or paragraph with no anchor at all if a comment or `#import` preceded it with NO blank line in between.** A third variant of the same symptom already fixed twice in this version (see above): an invisible line (comment/import) "spent" the "previous line was blank" flag the next line needs to receive its anchor. An invisible line no longer counts as one.
- **Reopening an already-inserted diagram (RF-31.3) and clicking "Insert" duplicated it instead of replacing it.** The button always wrote at the cursor position; now, if the editor was opened on an existing diagram, "Insert" replaces the whole `#figure(...)` block. Along the way, inserting the FIRST diagram into an empty document (which also needs to add the `#import`) left the cursor inside the CeTZ code itself instead of after the block — same code, simplified so it no longer needs a special case.
- **Pasting or dropping an image (RF-18/RF-39) could fail silently.** Neither handler caught an error from the underlying `FileReader`/IPC call: the paste or drop appeared to do nothing, with no warning at all.
- **The header's "File" and "Tools" menus did not close on an outside click**, despite their own comment claiming they did. `closeOnOutsideClick: true` was missing from the `registerPanel` call.
- **The shared Typst Universe search (RF-34/RF-34.7) filtered the entire catalog (~4,700 entries) on every keystroke, with no debounce at all.** Added a 200ms debounce, matching the one the outline and preview already use. Along the way, clearing the field while the first index download was still pending didn't cancel that search: it now does, and it can no longer repaint results over a field the user already emptied.

**Logged for a future session, not fixed in this pass** (Important, does not block v0.6.0's `/ship`):
- The citation assistant (RF-16/RF-35) now uses `hayagriva` to read the `.bib` file; a single malformed entry hides ALL citations from that file in the dropdown, instead of just the affected entry (`bibliography_keys`, more tolerant, still exists for other uses).
- The Universe search's "✓ Verified by DBV" badge is assigned by package NAME, not version: a version different from the one DBV actually reviewed inherits the same trust seal.
- `fetch_universe_index` sets no timeout on the HTTP request to the Typst Universe index; a broken or very slow network can hang the panel indefinitely.
- The conflict resolver doesn't recognize the `|||||||` marker of a `diff3`-style conflict (`git config merge.conflictstyle diff3`): the common-ancestor content leaks into the "Mine" side.
- `derive_clone_destination_name` (RF-33) doesn't handle a Windows-style local path (`C:\...`) pasted as a clone "URL" — an unlikely edge case in the real flow, but uncovered.

Also, 11 minor reuse/efficiency findings (duplication between `wireImageDrop`/`wireImagePaste`, an avoidable rebuild while dragging in the diagram editor, `universe_index.rs` cloning the full index on every call, among others) — no correctness impact, left for an unhurried cleanup later.

### Added
- **macOS signing and notarization conditioned on secrets (RF-36).** `release-macos.yml` passes the `APPLE_CERTIFICATE`/`APPLE_CERTIFICATE_PASSWORD`/`APPLE_SIGNING_IDENTITY`/`APPLE_ID`/`APPLE_PASSWORD`/`APPLE_TEAM_ID` variables to the build step; without those secrets configured (not yet, today) they arrive empty and the universal `.dmg`/`.app` ships unsigned, same as before — once they're configured, the same workflow starts signing without touching it again. The rest of RF-36 (universal Intel+Apple Silicon bundle, functional verification of the sidecars) and RF-37 (auto-updater: check, download, install, relaunch, clean Microsoft Store degradation) were already complete from Beta.
- **WYSIWYG diagram editor (RF-31), reduced scope.** New "✎" button in the editor toolbar, next to the CeTZ assistant (⬡) it will replace once it covers its 4 types without regression. SVG canvas with draggable rectangular nodes (pointer drag, in-place editable text), connected with arrows in "Connect" mode. Translates the result into readable `cetz.canvas` code and can reopen a diagram already inserted by this editor (not a hand-written CeTZ one) via a model serialized in its own comment. 2D plots and free-form canvas are left for a later iteration — a deliberate decision to avoid expanding scope without being able to validate it in a real window this session.
- **Full visual bibliography (RF-35).** The existing citation assistant (RF-17) is enriched: the dropdown label goes from showing only the key to "key — title — author, year", with a ⚠ warning if the entry is duplicated in the `.bib` or missing title/author. New `bibliography_entries` command parsed with `hayagriva` — the same engine the Typst compiler itself uses for `#bibliography()` — closing the question left open since the original spec about which BibTeX crate to use. `bibliography_keys` (lightweight scan) still exists for callers that only need the keys.
- **Full Universe Browser (RF-34).** Search across the entire Typst Universe catalog (~4,700 packages), not just the curated whitelist — new `fetch_universe_index` command (cached in memory after the session's first download) over `packages.typst.org/preview/index.json`, the same source the whitelist already used. Two-tier model: the curated list keeps the "✓ Verified by DBV" badge; any other result is marked "Community, unreviewed", with the same third-party notice already used on the gallery's "Address" tab. Deliberately behind a search box — nothing downloads or renders until something is typed.
- **JavaScript script insertion assistant with `jogs` (RF-38).** In the Tools menu: injects a deduplicated `#import "@preview/jogs:0.2.4": eval-js` and an editable `eval-js` template, with the 45s safety margin noted inline. Unlike the Python runner (RF-22), it launches no process and checks nothing installed on the system — `jogs` runs inside the compiler's own WASM plugin, so the assistant only inserts code, same pattern as the CeTZ diagram assistant.
- **45 s safety margin on every Typst compilation.** Sandboxing spike for RF-38: an `eval-js` script from the `@preview/jogs:0.2.4` package running an infinite loop hangs the `typst` process with no self-imposed limit (verified against the real binary, `spikes/jogs-sandbox/`). New `TypstError::TimedOut` and `COMPILE_TIMEOUT` in `typst_engine::compile::run_cancelable`: once the margin is spent, it kills the process and returns a readable error instead of hanging the operation forever. Applies equally to the live preview and to PDF/PNG export — protects any compilation involving third-party code, not just `jogs`.
- **"Tools" menu in the header (RF-32).** The advanced Terminal and Python Runner are no longer standalone icon buttons in the header — they now live under a single **Tools ▾**, together with "Clone repository" — the same criterion as the File menu from RF-30 (v0.5.0). The Git branch indicator does **not** move: it is a status meant to be seen at a glance (RF-19), not an action, so tucking it behind a menu would strip it of that value. No function loses its shortcut or behavior; `npm run verify:layout` confirms the header still fits on a single row at 830 px.
- **Clone repository by URL (RF-33).** Closes the gap acknowledged in v0.5.0 (`SPECIFICATIONS.md` §5e.1): until now the app could not clone a repository. A new `git_clone` command reuses the same non-interactive Git wrapper already used by `git_status`/`git_commit`/`git_push`/`git_pull` (`GIT_TERMINAL_PROMPT=0`, no credential custody), and works the same with GitHub, GitLab, Codeberg, or SSH — it was not tied to a single platform, an explicit user decision among the 5 alternatives evaluated for v0.6.0. The destination folder name is derived from the URL the same way `git clone` itself does, and it never overwrites an existing non-empty destination. Available from "Clone repository" in the launcher and the File menu; after cloning, it opens the project directly.

## [0.5.0] - 2026-09-09

### Added
- **Two more automated checks** (`verify:frontend` 10→11, `verify:layout` 14→15). *No repeated id in `index.html`*: a duplicate id throws nothing — `getElementById` returns the first one and the second element sits dead on screen, looking normal and reacting to nothing — and it is the direct risk of repeating an action in two places, as the File menu does with "Import project". And *the action bar leaves room for the brand*, pinning in the real engine the width RF-30 has just freed.
- **The `verify:layout` probe now builds the REAL header and launcher** (`scripts/layout-probe.html`), going from 9 to 14 checks. The header used to be a one-line stand-in — `<header><span>cabecera</span></header>` — that could not reveal anything, and the launcher still carried the template grid RF-25 removed: the probe was measuring a screen that no longer ships. It now checks that the header **stays on a single row at 830 px** (the width at which the user saw it broken), that the product name does not wrap, that the brand items do not overlap, that the start block fits its container, and that the three secondary actions stay on one line. Validated against the bug, as this project does: with the previous CSS two of them fail, at 88 px of header and 63 px of title.
- **A "keep window on top" pin (RF-28).** The user missed it — "it is essential in my applications and they all have it" — and there was nothing to invent: it is ported from DBV Markdown Reader with the same pictogram, because the same action should not have two different drawings across the family. It is **per window and not persisted**, replicating the decision already taken there: pinning a window on top is a decision of the moment, not a permanent preference, and always starting above everything else would be surprising. Tauri's `core:default` does not include the window capabilities that mutate state, so only the two needed are added (`allow-set-always-on-top`, `allow-is-always-on-top`), exactly as the header of `capabilities/main.json` states. If the call fails, the control **does not lie about its state**: it only shows as active once the window confirms it.

### Fixed
- **The header broke into three rows with a project open and a narrow window.** `.app-header__actions` is declared `flex: 0 0 auto` — it never shrinks — so all the pressure from a tight width fell on the brand; and since `.app-header__title` had no `white-space: nowrap`, the product name split into "DBV / Typst / Editor" and stretched the header to 88 px tall. Reported by the user with a screenshot. The title now never wraps, the project name is the only thing that shrinks (it already ellipsised, and it is the only value whose abbreviated form still works), and everything else is declared `flex: none`. While there, the brand was aligning items of very different sizes on their baseline — title, name, badge and a button — which left them stepped: it now aligns on centre.
- **`verify:layout` was skipping itself with a working browser right there.** The script picked the **first** installed candidate — Edge — and never checked whether it answered; Edge's `--dump-dom` returns empty output on this machine (on a trivial page too), so the project's only geometry check was silently skipped with Chrome installed. It now tries candidates until one answers, and reports which one it used.
- **A Python script printing more than about 64 KB hung until the timeout expired (`commands/python_runner.rs`).** The child process was spawned with its `stdout`/`stderr` pipes connected, but the parent did not read them until **after** it had finished. A system pipe buffer is around 64 KB: once full, Python blocked on write, never exited, and the wait loop burned the whole timeout. The user saw *"execution time exceeded"* — losing all output — on a perfectly correct script; a `print` of a large DataFrame or a verbose Matplotlib run reaches that size effortlessly, and that is precisely the use case RF-22 exists for. The pipes are now drained on separate threads while the process runs. Regression test with 300 KB of output: it used to burn the full 30 s limit and fail, and now finishes in a little over a second.
- **The Git indicator showed any filename containing spaces incorrectly, and the old name for renames (`commands/git.rs`).** The `git status --porcelain=v2` parser took the path with `split_whitespace().last()`, so `mi documento.typ` showed up as `documento.typ` — a file that does not exist under that name — and on a rename line it returned the ORIGINAL path, which comes after the tab, instead of the new one. On a truncated line it went as far as listing `100644` as a modified file. The path is now extracted by skipping the format's fixed fields and cutting at the tab. Reproduced against real `git` beforehand, and the tests carry that literal output.
- **Accented names arrived octal-escaped (`commands/git.rs`).** `core.quotePath` is on by default, so `sección.typ` came through as `"secci\303\263n.typ"`, quotes included, and was painted that way in the Git panel. In an editor meant for writing in Spanish that is the normal case, not the rare one: the commands now run with `-c core.quotePath=false`.
- **Status colors did not follow the theme (RF-27).** The v0.5.0 features introduced a hand-written palette (`#10b981`, `#ef4444`, `#f59e0b`, `#3b82f6`…) in the Git indicator, the LSP diagnostics and the Python panel. Not being tokens, in the sepia theme they showed as four cold, saturated colors on a warm palette — the very defect `--band-hint` already fixed once, after a real user reported it. They are now `--status-ok`, `--status-warn`, `--status-error` and `--status-info`, with their own value per theme; in sepia they are drawn from the palette that theme already uses for code, so they introduce no foreign hue.
- **`--accent-subtle` was used but never existed.** `layout.css:1148` read it with a fallback (`var(--accent-subtle, rgba(2, 132, 199, 0.15))`), and since the token was never declared **the fallback always won**: the gallery search box's focus ring was a fixed blue even in sepia. Now declared in all three themes.
- **`font-family: var(--font-sans)` pointed at a token that does not exist** (`base.css`, the Typst Universe hover tooltip). The interface token is `--font-ui`; with no fallback, `var()` on a missing token paints nothing, so that tooltip inherited its font by accident throughout v0.5.0. Caught by one of the two new `verify:frontend` checks.
- **Two transitions with hand-written values** (`0.15s ease`) in the gallery search box, instead of `var(--transition)`.
- **A button removed from the HTML could stop the whole app from starting.** `registerPanel` built its triggers with `[].concat(opts.trigger)` without filtering, and `el('x')` returns `null` once the element is gone: the following `addEventListener` threw during initial wiring. It came within one step of happening while removing `#btn-launcher-universe`. Fixed with `.filter(Boolean)` and three regression tests.
- **The release workflows would have failed to package v0.5.0 (`ci.yml`, `release-linux.yml`, `release-macos.yml`).** With Tinymist declared as a second sidecar in `bundle.externalBin`, no workflow vendored it: only `npm run vendor:typst` was ever called. CI stayed green because it packages nothing, so the failure would only have surfaced with the tag already pushed, when `tauri build` aborted on the missing `binaries/tinymist-<triple>` — the same pattern that shipped the Store package without a compiler inside in v0.3.1. Linux and macOS now vendor both sidecars and verify both before building; on macOS each one is fused with `lipo` into a universal binary, because `--target universal-apple-darwin` requires the `-universal-apple-darwin` suffix for every sidecar. CI vendors them too, even though it packages nothing, so that a renamed Tinymist asset is caught on every push rather than mid-release.
- **`verify:layout` reported a bogus "the probe crashed" (`scripts/verify-layout.mjs`).** Two bugs in the verifier itself, neither of them layout: (1) a browser exiting with code 0 and writing nothing to stdout — headless Edge on some machines, even for a trivial page — was counted as a broken probe; it is now SKIPPED, exactly as when no browser is found, and the failure message is reserved for a DOM that comes back without results inside it; (2) on Windows the temporary-profile cleanup blew up with `ENOTEMPTY` because the browser still held files open, killing the check in its `finally`; it now retries and, failing that, leaves the temp directory alone.

### Added
- **Slice 30 — Editor ↔ preview synchronisation (RF-16).** Double-clicking the render takes the cursor to the source, **opening the relevant chapter** if it is not the one on screen; and a button in the bar takes the preview to wherever the cursor is. Since Typst exposes the source position of nothing it renders (ADR-SYNC-001), the bridge is manufactured: `shadow.rs` seeds the replica with `#metadata((f: …, l: …))<dbv-sync>` anchors and `typst_sync_anchors` collects them with a `query` that returns our own payload and `location().position()` in a single pass. The table is computed **on demand and cached per generation** — it costs another full composition of the document, ≈750 ms at 202 pages — and a table from a superseded generation is never applied. **Two things building uncovered that the spike had not:** (1) seeding breaks any file containing code blocks — `#let documento(..) = { .. }`, which is exactly what the 8 curated templates ship — with `the character '#' is not valid in code`; the failure surfaced while compiling `testfiles/demo-proyecto` against the real binary, because the spike's fixtures were pure markup. Seeding now tracks delimiter depth outside strings and comments, and only anchors in top-level markup. (2) Lookup orders by **(page, x band, y)** rather than (page, y), because in two columns the second has a lower `y`; and a click with no anchor ahead of it — a floating figure, drawn above everything anchored — falls back to the nearest anchor by absolute distance instead of giving up. Verified end to end against the binary: 22 anchors on the demo project, 0 out of order, 0 lines outside their original file's range, and **the SVG comes out identical with and without anchors**, confirming that seeding changes nothing of what the user sees.

New requirements in `SPECIFICATIONS.md` §5b: **RF-14** preview compiles the root document, switchable back to "this file only"; **RF-15** automatic/manual refresh control; **RF-16** bidirectional synchronisation via anchors; **RF-17** a dropdown of the project's images on the "Fig" button, with "Browse for an image…" as the last option; **RF-18** image drag-and-drop accepted anywhere in the window, as fonts already are. **Specification amendment (`ADR-SYNC-001`):** §6 and §11 promised the sync *"by real source position (not by anchors)"* via the `tinymist` LSP; the spike shows that is unreachable from the sidecar, and §9 had already discarded `tinymist` for the very same purpose — the spec contradicted itself and nobody had noticed — so the clause is replaced by the anchor mechanism with its limitations (block-level precision, ordering by x band in two-column documents, floats unresolvable by position) written into the spec itself. A note on RF-18: image drag-and-drop **already existed** since Slice 19, but required dropping inside the editor pane while the font equivalent accepts the whole window; dropping onto the project explorer did nothing **and did so silently**, which is what led a user to believe the feature was already there.
- **Spike S-2 — Editor ↔ preview synchronisation (research, no production code).** Prompted by a user asking for the bidirectional double-click other editors have, and by the problem that request exposes: the preview compiles **the open file**, not the root document, so editing a chapter leaves no possible correspondence with `main.typ`. Full report in `spikes/preview-sync/README.md`, everything measured against the vendored binary. Main results: **(1)** Typst offers **no native render→source bridge** — no `span` in the scripting API and no annotation whatsoever in the SVG — so with the sidecar architecture the injected-anchor mechanism is mandatory; **(2)** that mechanism works: `query(<dbv-sync>)` returns both our own payload (file + line) and `location().position()` (page, x, y), and `#metadata` anchors placed between blocks leave the SVG **byte-for-byte identical**, at a cost of 0.007 ms per anchor; **(3)** the risk identified while planning — that the unsaved-changes mirror does not travel through an `#include` — is solved by replicating the project into a temporary shadow root, at a 2 % overhead (18 ms against 826 ms of compilation); **(4)** the real chapter in `testfiles/demo-proyecto` **does not even compile on its own** (`label <knuth1984> does not exist`), confirming that the current scope is not merely suboptimal but incorrect. **Finding that changes the plan:** compiling the whole document costs **9×** what compiling the chapter does (828 ms against 91 ms on a 202-page thesis) and exceeds the 350 ms typing pause, so the automatic/manual refresh control goes from a convenience to a **requirement**. Two concrete limitations of the reverse path are also documented: two-column layouts force ordering by (page, x band, y) rather than (page, y), and floats cannot be resolved by position because `location().position()` returns their in-flow position, not where they are drawn.

### Fixed
- **Preview scroll reset on double-click navigation.** Fixed an issue where double-clicking the render to jump to an editor line caused the preview to jump back to page 1 in multi-chapter projects; the render now preserves the scroll position unless the underlying target document changes.
- **On macOS, opening a `.typ` from Finder launched the app but not the document (RF-12).** Reported by a macOS user: both double-clicking and "Open with" left the app sitting on the launcher, with the document lost. The file association itself was fine (which is why the app did open); what was missing was the Rust side. The whole open-from-OS mechanism was built on `argv` — `startup_document` for a cold start, the `tauri-plugin-single-instance` handler for a warm one — and **macOS never passes the file as a command-line argument**: Finder delivers the open as a `kAEOpenDocuments` Apple Event, exposed in Tauri v2 solely through `RunEvent::Opened { urls }`. Our own `NATIVE_DESKTOP_APPS.md` §8 documented this exact trap and `ARCHITECTURE.md` listed it as a component to port (item 4); it was never ported, and `ARCHITECTURE.md` §1.5 claimed the very opposite ("100% declarative, no extra Rust code") — line corrected. `lib.rs` now uses `.build(...)` plus its own event loop to intercept `RunEvent::Opened`, and `commands/startup.rs` turns the URL into a path with `to_file_path()` (essential: Finder escapes the path, so a `tesis de doña.typ` travels as `tesis%20de%20do%C3%B1a.typ` and does not exist on disk undecoded). Since the Apple Event arrives **before** any window exists, the path is stashed in a managed `PendingDocument` state that the frontend drains on its initial `startup_document` call; if the frontend is already alive (app open, second double-click) the existing `open-document` event is emitted directly. No frontend changes, and Windows/Linux keep the `argv` path exactly as it was.

## [0.3.1] - 2026-09-07

> Corrective release. The MSIX package published on the Microsoft Store shipped **without the Typst compiler and without the template catalogue inside**: the app opened and let you edit, but every compiler-dependent feature (live preview, PDF/PNG export, advanced terminal, create project from template) failed with `os error 2`. ### Fixed
- **The Microsoft Store `.msix` was published without the `typst.exe` sidecar (critical).** `@choochmeque/tauri-windows-bundle` (v0.1.29, the latest published) **does not implement `bundle.externalBin` at all**: its `prepareAppxContent()` copies the main executable, the `Assets` and `bundle.resources`, and never the external binaries. Since Tauri always invokes the compiler as a sidecar and never looks at the system PATH's `typst` (a deliberate decision, `memory.md` 2026-09-04), the child process was never spawned at all, and the error the user saw was the raw `Command::spawn` one — with no Typst diagnostic formatting, which is precisely what gave away that the failure was not in the compiler but in launching it. Fixed with a persistent patch (`patches/@choochmeque+tauri-windows-bundle+0.1.29.patch` via `patch-package`, reapplied only on each `npm install`). **Useful diagnostic symptom: the package goes from ~6 MB to ~30 MB** — a 51 MB compiler does not fit inside 6 MB.
- **The sidecar must be copied WITHOUT the target triple suffix.** First version of the patch: it was copied as `typst-x86_64-pc-windows-msvc.exe` (the vendored file's name) and the failure persisted identically. `tauri-plugin-shell` resolves `sidecar("typst")` to `<folder of the running executable>/typst.exe` (`relative_command_path()`), with no triple: Tauri's official bundler renames it at packaging time. It is now copied as `typst.exe`.
- **`bundle.resources` with a `../` prefix was copied OUTSIDE the package root.** In array form and with no explicit `target`, the tool did `path.join(appxDir, "../templates")`, leaving `templates/` as a *sibling* of the folder that later gets packaged (`target/appx/templates/` instead of `target/appx/x64/templates/`) — that is, outside the `.msix`. That is why the template catalogue came up empty on a second computer. The patch normalises the destination inside the package root.
- **The advanced terminal never set the working directory (affects ALL platforms, not just the Store).** `typst_run_raw` launched the sidecar with no `current_dir`, so the process inherited the application's own directory rather than the open project's: any relative path typed by the user (`compile main.typ`) failed with "file not found", even though the panel advertises itself as a direct line to the compiler *on this project*. It now receives the active project root and sets it as `current_dir`.
- **Extended-length `\\?\` path prefix on Windows.** `fs::canonicalize` always returns the *verbatim* form on Windows (`\\?\D:\...`), which leaked into the interface — visible in the document title bar and in the "Recent projects" list. Replaced with `dunce::canonicalize` in `project.rs`, `commands/file_io.rs` and `archive.rs`, and `dunce::simplified` on the `--package-path`/destination arguments passed to `typst init` in `templates.rs`. *(Honesty note: this prefix was at one point suspected of being the root cause of the `os error 2`; that was ruled out by checking against the real binary that `typst.exe` accepts `\\?\` paths without trouble. The change is kept for correctness and interface hygiene, not as the fix for the critical failure.)*
